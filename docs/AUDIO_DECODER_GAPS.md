## 第四轮：两个确定性 bug 的真修

### V1 · Vorbis MDCT 归一化（位级修复）

`MdctBackward` 原写 `twoOverN = 4.0 / n`。谐波级诊断（`45623098197`）显示：

```
VORBIS off=109 corr=0.96824 rms=0.00437
seg=[0.94173,0.99941,0.99949,0.99935,0.99944,0.99945,0.99947,0.94325]
harm=[440:0.00211/0.49968, 1320:0.00085/0.19859]  相位差仅 0.78° / 2.28°
```

**波形形状几乎完美（中间 6 段 corr 0.9994+）、相位正确，唯独幅度缩小约 230 倍** →
不是算法精度，是全局标量。根因：Vorbis 的 `floor × residue` 输出是**已归一化频谱**，
与 libvorbis `mdct_backward` 的直接求和定义一致，逆变换不该再乘 `4/N`；该系数把
时域幅度缩小约 `n/4` 倍（长短块混合后实测 ≈ 1/229）。

改为 `norm = 1.0` 后（`45624810254` / `45625573880`）：

```
VORBIS pcmLen=8000 off=0 corr=1.000000 n=8000
mdBest=0.00000 corr0=1.000000 n0=8000 md0=0.00000 rms=1.000000 dc=-0.00000
seg=[1.00000 ×8]
harm=[440:0.49971/0.49971/-0.00000, 1320:0.19859/0.19859/-0.00000]
head=[0.12767/0.12767, 0.26779/0.26779, 0.36004/0.36004, ...]
```

**逐样本位级匹配 libsndfile 参考**。用例已从看板移除、回归真实门禁，
`SelfCheckTests` 新增断言「Vorbis 不得再被隔离」。

> 上一版台账里写的「V1 待核对 4/N vs 2/N」方向是错的：不是差 2 倍，
> 是根本不该带 `1/n`。已按实测更正。

### M1 · MP3 Xing/LAME gapless 裁剪

本地解析 `sine16k_mono.mp3`（Python，无需 .NET）：

```
Xing @ 13, flags=0xf, frames=16, bytes=2160
LAME3.100 @ 133 → enc_delay=576, enc_padding=640
17 个物理帧 × 576 = 9792 样本；参考解码输出 8000
16×576 − 576 − 640 = 8000  ✓
```

原 `DecodeAll` 把 Xing 元数据帧也计入 PCM、且完全不做 gapless 裁剪，输出 9792 样本。
诊断（`45623098197`）显示前 7 段 corr 0.991~0.994、**第 8 段 0.30514**，整体 0.90764，
对齐搜索找到虚假的 `off=-2336`（靠缩短重叠窗口避开尾部垃圾）。

修复：`ParseGapless()` 解析首帧 Xing/Info flags 与 LAME `enc_delay/enc_padding`；
`DecodeAll` 跳过元数据帧、跳过编码延迟、丢弃尾部填充。结果：

```
MP3 pcmLen=8000 off=-1584 corr=0.99263 n=6416
rms=1.00374 dc=0.00103
seg=[0.99269,0.99397,0.99397,0.99285,0.99393,0.99382,0.99342,0.98686]
harm=[440:0.50316/0.50115/4.53894, 1320:0.19942/0.19991/13.70082]
```

末段从 0.305 → 0.98686，相关系数从 0.90764 → **0.99263（越过 0.97 门槛）**。

## 第五轮：撤回「亚样本相位」归因（重要更正）

上一轮据 `4.54° @440Hz / 13.70° @1320Hz` 推断「≈0.46 样本的分数延迟」。
这轮用**分段 RMS / 固定窗口对齐 / 误差位置分桶 / 亚样本插值**四项诊断推翻它：

| run | 关键证据 |
|---|---|
| `45806756991` | 全量 skip 扫描：`s=1365 md=0.19002 corr=0.99533`；误差 >0.1 的 38 个样本**全部落在第 8 桶（6400~7200）**；`SUBSAMPLE` 扫描 frac=-1..1 最小 md 仍 0.19002 → **不是亚样本相位** |
| `45807569040` | 固定 6000 窗口：`s=1329 md=0.02348 corr=0.99990`，10 个 600 样本桶内 **0 个 >0.05 误差**；`RMS_PCM` 前 400 样本 0.00565（静音），`RMS_RF` 前 400 样本 0.38016（满幅）；`PRELUDE zeroCount=396 maxRun=336 at=0` |
| `45808650705` | gapless 位移 D 扫描 0..640：`md` 最小仍 1.296 / `corr` ≈0 → **补偿量远超 enc_padding(640)，单纯平移裁剪不够** |

结论分三层：

1. **解码主体是对的**：内部对齐后前 6000 样本 `md=0.02348 / corr=0.99990`，
   谐波幅度 0.50316/0.50115、0.19942/0.19991，与参考几乎重合。
   上一版归因为「算法精度差」和这一版之前的「亚样本相位」**都不成立**。
2. **解码器固有延迟未补偿**：输出前约 336~396 个样本是 QMF/IMDCT 预热静音，
   而 libsndfile 参考从第 0 样本就是满幅。需再前移约 **1329 样本**（不是 0.46）。
   `DiagShift` 在 0..640 范围内无解，说明不能靠 `enc_padding` 内部挪窗口解决，
   必须从**解码器状态预热/输出口径**层面补，且不能牺牲 8000 样本长度。
3. **末帧局部畸变**：6400~7200 有 38 个样本 >0.1，集中在 6550~6640
   （`ERR_TOP` 6576 / 6586 / 6628 / 6587 / 6629…），疑似最后一帧的
   bit reservoir / `L3RestoreReservoir` 边界处理。

> 这轮没让看板从 1 变 0，但把「算法级偏差」这个模糊归因彻底拆成了两个
> **可定位、可单独验证**的具体缺陷。证伪本身是进展。

## MP3 剩余问题（第五轮精确定义）

`corr0=-0.78250`：不做对齐时几乎反相，说明 `off=-1584` 是**真实编码器延迟**而非搜索偏置，
对齐是必要的。剩余 `maxAbsDiff=0.24488` 来自：

- 谐波相位差 `4.54° @440Hz`、`13.70° @1320Hz` → 两者一致，**≈ 0.46 样本的分数延迟**；
- 对齐后前 10 个样本差 `0.076 / 0.050 / 0.024 ...`，是系统性相位差而非孤立尖峰；
- 第 8 段 0.98686 略低，提示尾部仍有帧边界残差。

### 数值验证计划 M1–M6

| ID | 验证点 | 状态 | 方法 / 判定 |
|---|---|---|---|
| M1 | 亚样本相位 | ❌ **已证伪** | `SUBSAMPLE` frac=-1..1 最小 md 仍 0.19002，排除 |
| M2 | `L3Imdct36` 窗归一化 | ⏸ 搁置 | 前 6000 样本 md=0.02348 已足够好，非当前瓶颈 |
| M3 | `Mp3dSynthPair` 相位 | ⏸ 搁置 | 同上 |
| M4 | 解码器固有延迟 | ▶ **主攻** | 在 `Reset()` 后预热 QMF/IMDCT overlap，或按 MPEG2 L3 规范硬编码 decoder delay；判定：pcm[0]≈rf[0] 且长度仍 8000 |
| M5 | 末帧 bit reservoir | ▶ **主攻** | 打印每帧 `mainDataBegin` / `L3RestoreReservoir` 返回值，定位 6576 落在哪帧；判定：该帧输出与参考逐样本差 < 5e-2 |
| M6 | 比较口径 | ▶ 待 M4/M5 后定 | 若 M4 使 pcm[0] 对齐，则 `CompareWithReference`（零对齐）应直接通过，无需 `Aligned` 版本 |

**判定规则**：相关系数与 maxAbsDiff 阈值**不放宽**；`corr` 已达 0.97 但整体
`maxDiff` 未达 5e-2，因此条目保留。禁止用缩短比较窗口来制造假绿——
`45807569040` 的「固定 6000 窗口 md=0.02348」只是**诊断证据**，不是验收口径。
