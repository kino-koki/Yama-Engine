03 / What you can build

Not just an engine —
a complete workflow.

Yama is more than a runtime. From modeling to deployment, visual scripting to DCC bridging, it aims to cover every step of desktop AAA development. This page explains the three main workflows and how they connect inside one window.

Most engines let you "make a game inside the engine". Yama tries to let you "finish everything from assets to release inside one window" — modeling, terrain, animation, code and testing, five modes one click away, without leaving the process.

Workflow 1 · 3D game prototyping

Physics-driven, state-synced, hot-reloaded scripts — press Play in the editor to test immediately; change one line of C# and see the result at once. The prototyping phase needs "edit, then run instantly" more than anything else. Yama's Roslyn hot-reload + ECS system scheduling exist to make that loop imperceptible.

  1. Block out geometry in modeling mode and export it as engine meshes.
  2. In scene mode, attach RigidBody + Collider components.
  3. In code mode, write one line of C#, hot-reload, press Play.
  4. The physics solver advances the rigidbody, the render system reads Transform, the viewport updates instantly.

Workflow 2 · Terrain & scene editing

Five editing modes one click away: scene, terrain, modeling, code, test. Terrain sculpting, object placement, NavMesh baking, light baking — all done in the same window. No switching to Houdini, no switching to Substance, no switching to another engine.

Terrain mode

Heightmap Sculpt

Sculpt heightmaps with brushes, generate normals in real time, and bake NavMesh walkable areas in the same pass.

Scene mode

Transform Gizmo

Translate / rotate / scale gizmos, with a hierarchy tree, inspector panels and a content browser.

Workflow 3 · Live DCC tool bridging

Change one vertex in Blender and the Yama viewport refreshes in sync. Push Maya / 3ds Max assets with one click — no export/import ping-pong. The LiveLink TCP plugin syncs meshes and animation in real time; Python plugins push assets into the engine's asset pipeline.

The point of this workflow: you don't have to change your modeling habits to use Yama. Prefer Blender? Keep using Blender. Prefer Maya? Keep using Maya. Yama catches you on the other end.

Honest Note

The DCC bridges are skeleton-level today — data flows, but there's no production-grade testing. Maturity for this area is 30%; details on the Honest Status page.

One scene, three views

  • Viewport view: the real-time Vulkan render — PBR + cascaded shadows + TSR.
  • Outline view: the scene hierarchy tree; drag to change parenting.
  • Inspector view: component panels for the selected object, ImGui-driven; value changes write back instantly.
