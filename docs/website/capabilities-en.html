Render pipeline

113 files · C#

PBR materials, skeletal skinning, cascaded shadows, temporal anti-aliasing (TSR) and foliage rendering are wired into the SceneRendererReal pipeline. ReSTIR global illumination and path tracing exist at the algorithm layer, awaiting end-to-end GPU validation.

PBRCascade ShadowTSRSkinningReSTIR

Deep dive

Deferred path + full post-processing stack: bloom, depth of field, tone mapping, vignette, chromatic aberration, lens flare, TAA; transparent objects use the forward path. PBR uses Cook-Torrance BRDF; cascaded shadows support 4 cascades. ReSTIR / SVGF / path tracing have complete algorithm and shader code, pending GPU validation.

Physics engine

82 files · pure C#

Zero dependencies. GJK / EPA / SAT collision detection, 9 joint constraint types, custom vector & quaternion libraries, shape dispatchers, fluid and cloth simulation — all hand-written from the math up, with no third-party physics library.

GJKEPASAT9 JointsFluidCloth

Deep dive

Collision detection includes GJK (Gilbert-Johnson-Keerthi), EPA penetration depth and SAT (OBB / AABB / capsules); the constraint solver supports hinge, slider, ball-and-socket and 6 other joint types; cloth uses Verlet integration; fluid mixes Eulerian grids and particles. Tests verify against analytic solutions: free fall, impulse-momentum, angular momentum conservation, Coulomb friction, restitution.

Artificial intelligence

35 files · C#

NavMesh baking, A* / D*Lite / JPS+ / Theta* pathfinding, GOAP goal-oriented planning, behavior trees, ORCA crowd avoidance. LLM-driven NPC dialogue integration in progress.

NavMeshA* / JPS+GOAPBehavior TreeORCA

Deep dive

NavMesh uses Recast-style voxel baking + triangulated queries; pathfinding ships four implementations (A*, JPS+, Theta*, D*Lite); GOAP supports preconditions/effects with plan reuse; behavior trees have blackboards and decorators; crowd avoidance is an ORCA implementation based on the RVO2 paper. On the LLM side, NpcBrain feeds JSON intents from a large model into behavior trees and StateTree.

Animation

34 files · C#

Motion Matching procedural clip selection, FABRIK / CCD / Two-Bone IK solvers, animation state graphs, skeletal retargeting — a complete toolchain for character animation and procedural motion.

Motion MatchingFABRIK IKCCDRetargeting

Deep dive

Motion Matching selects clips in real time from the animation library using trajectory matching (future trajectory + pose cost). IK ships three solvers: FABRIK, CCD and Two-Bone. Retargeting supports bone mapping with offset correction. Status: core algorithms done; editor preview integration in progress.

Audio

35 files · C#

Dual output backends (WASAPI and Miniaudio), FFT spectrum analysis, DSP effect chains, convolution reverb, a real-time synthesizer, and 3D spatial audio — from low-level DSP to the audio scene graph.

WASAPIFFT / DSPConvolution Reverb3D SpatialSynth

Deep dive

Dual backends: WASAPI (exclusive/shared modes) and Miniaudio. The DSP chain includes EQ, compressors, delays and reverb; convolution reverb uses FFT partitioned convolution; 3D audio applies an HRTF approximation from listener orientation. Status: backends and DSP done; audio scene graph integration in progress.

ECS architecture

19 files · C#

Archetype memory layout keeps component data contiguous for maximum cache hit rate. SystemScheduler manages execution order, EntityCommandBuffer defers entity operations, EntityQueryCache accelerates queries.

ArchetypeSystemSchedulerCommandBufferQueryCache

Deep dive

Archetypes store entities in chunks per component combination, with 16KB chunks aligned to cache lines; SystemScheduler sorts by read/write dependencies and builds parallel groups; EntityCommandBuffer records and replays deferred changes; EntityQueryCache caches query results. Status: core done; benchmarks in progress.

Integrated editor

41 files · WinUI 3

A WinUI 3 native window hosting a Vulkan surface, with ImGui-driven viewport, outline and inspector panels. Five work modes one click away: scene, terrain, modeling, code, test.

WinUI 3ImGuiViewportInspector5 Modes

Deep dive

The WinUI 3 native window embeds a Vulkan surface via Win32 swapchain interop; ImGui panels include viewport, hierarchy outline, component inspector, console and asset browser; the five modes (scene / terrain / modeling / code / test) share one undo stack. Status: panels and mode switching work; UX polish ongoing.

DCC bridges

Blender · Maya · Max

A Blender LiveLink TCP plugin syncs meshes and animation in real time; Maya and 3ds Max Python plugins push assets into the engine's asset pipeline. Keep the modeling tools you already use.

Blender LiveLinkMaya3ds MaxAsset Pipeline

Deep dive

The Blender side is a Python plugin + TCP LiveLink pushing meshes / skeletons / animation in real time; Maya and 3ds Max export intermediate formats via OpenMaya / MaxScript into the asset pipeline. Status: the Blender link runs basic mesh sync; Maya / Max are skeleton-level implementations.

Networking · assets · scripting

Multiple subsystems · C#

LiteNetLib state replication with client prediction for multiplayer sync; ProjectSystem and AssetDatabase drive the data asset pipeline; Roslyn provides C# hot-reload scripting, plus a visual script editor.

LiteNetLibState ReplicationRoslynVisual Script

Networking: LiteNetLib transport + state replication (snapshot interpolation) + client prediction with server rollback. Assets: ProjectSystem / AssetDatabase support import, references and packaging. Scripting: Roslyn-based C# runtime hot-reload. Status: network replication and script hot-reload work.

Deep dive · how three systems cooperate

The nine cards above are the horizontal "what exists". This section is the vertical "how it cooperates". A moving crate in a game passes through physics, rendering and ECS at the same time:

  1. ECS Transform components hold position and rotation; a RigidBody component declares participation in physics simulation.
  2. The physics solver advances velocity and position at a fixed step and writes back to Transform.
  3. The render system reads Transform, writes a unified model-matrix cache, and hands it to Vulkan push constants / UBOs.
  4. The animation system modifies vertices via skeletal skinning while Motion Matching picks the clip — all on the GPU side.
  5. The audio system computes 3D attenuation from listener-to-source distance and outputs to WASAPI / Miniaudio.
Honest Note

File counts measure "how much code exists", not "how stable it is". The render pipeline is at 60% maturity, DCC bridges at 30% — itemized numbers live on the Honest Status page.

Technology choices at a glance

Graphics API

Vulkan 1.4 · Silk.NET 2.22

The only backend. Dynamic rendering, mesh shaders, ray tracing and bindless resources are all available. D3D12 has been removed.

UI framework

WinUI 3 + ImGui

Native window hosting a Vulkan surface. ImGui drives the viewport / outline / inspector; WinUI 3 provides system menus and dialogs.

Scripting

Roslyn C# Hot-Reload

C# scripts compile and hot-reload at runtime — change one line and see the result immediately. A visual script editor is also included.

Audio backend

WASAPI + Miniaudio

Dual output backends with a DSP effect chain, convolution reverb, a real-time synthesizer, and 3D spatial audio.
