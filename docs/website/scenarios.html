03 / What you can build

不只是引擎，
是一个完整的工作流。

Yama 不只是一个运行时。从建模到部署，从视觉脚本到 DCC 桥接，它试图覆盖桌面 3A 游戏开发的每一个环节。这里讲清三大工作流，以及它们是怎么在一个窗口里连贯起来的。

大多数引擎让你"在引擎里做游戏"。Yama 试图让你"在一个窗口里完成从资产到发布的全过程" — 建模、地形、动画、代码、测试，五种模式一键切换，不用跳出这个进程。

工作流一 · 3D 游戏原型

物理驱动、状态同步、热加载脚本 — 在编辑器里按 Play 立刻试玩，改一行 C# 立刻看到效果。原型阶段最需要的就是"改完立刻跑"，Yama 的 Roslyn 热加载 + ECS 系统调度就是为了让这一循环短到无感。

  1. 在建模模式里摆好几何体，导出为引擎网格。
  2. 在场景模式里给刚体挂 RigidBody + Collider 组件。
  3. 在代码模式里写一行 C#，热加载，按 Play。
  4. 物理 solver 推进刚体，渲染系统读 Transform，视口即时更新。

工作流二 · 地形与场景编辑

五种编辑模式一键切换：场景、地形、建模、代码、测试。地形雕刻、物体摆放、NavMesh 烘焙、光照烘焙 — 全部在同一个窗口里完成。不需要切到 Houdini、不需要切到 Substance、不需要切到另一个引擎。

地形模式

Heightmap Sculpt

笔刷雕刻高度图，实时生成法线，配合 NavMesh 烘焙把可行走区域一并算好。

场景模式

Transform Gizmo

平移 / 旋转 / 缩放 gizmo，大纲树、检查器面板、内容浏览器齐备。

工作流三 · DCC 工具实时桥接

Blender 里改一个顶点，Yama 视口里同步刷新。Maya / 3ds Max 资产一键推送，不需要导出导入的来回折腾。LiveLink TCP 插件实时同步网格与动画，Python 插件把资产推送进引擎资产管线。

这条工作流的意义在于：你不必为了用 Yama 而改变你的建模习惯。喜欢 Blender 就继续用 Blender，喜欢 Maya 就继续用 Maya，Yama 在另一端接住你。

Honest Note

DCC 桥接目前处于骨架级实现 — 数据能收发，但未做生产级测试。这一块的成熟度是 30%，详见 真实状态。

一个场景，三种视图

  • 视口视图：Vulkan 渲染的实时画面，PBR + 级联阴影 + TSR。
  • 大纲视图：场景层级树，拖拽即可改变父子关系。
  • 检查器视图：选中对象的组件面板，ImGui 驱动，改数值立刻写回组件。
