05 / Honest Status

We tell you the real state,
not marketing talk.

Most engine websites only show what succeeded. Yama does the opposite — finished and unfinished work are presented with equal clarity, because transparency is an open-source project's greatest asset. Maturity, build results and roadmap follow in three parts.

05-A Maturity

What's real,
and what needs time.

Yama's physics, AI, animation, audio and ECS systems are fully implemented at the algorithm layer. PBR, cascaded shadows and skeletal skinning in the render pipeline are wired into the main pipeline. But ReSTIR global illumination, path tracing, MicroCluster and other advanced features remain algorithm prototypes.

All managed projects reached 0 compile errors on 2026-11-01 — but compiling is not GPU end-to-end validation. Vulkan runtime crashes still need debugging on real hardware.

  • Physics: GJK / EPA / SAT collision detection and all 9 joint constraint types are implemented, with unit test coverage
  • Rendering: PBR + cascaded shadows + TSR are wired into SceneRendererReal; runtime stability still needs validation on a discrete-GPU machine
  • ReSTIR, SVGF and path tracing have complete algorithm code, waiting to be integrated into the main pipeline and run on GPU
  • DCC bridges (Blender / Maya / Max) are skeleton-level: basic data flows, but no production-grade testing
  • The C++ native bridge (YamaEngineBridge) requires Visual Studio MSBuild and is not yet in automated CI

05-C Roadmap

Next: make it
actually run.

Between "it compiles" and "it runs" lies a real GPU end-to-end validation — currently the most concentrated piece of work in Yama.

Done · 2026-11-01
Zero compile errors across all managed projects
Engine library, editor, tests, runtime and bridge projects all at 0 errors. P0 crash-defense patches landed: PSO null-handle guards, pipeline creation validation, cross-frame cache clearing.
In progress · Phase 1
Real GPU end-to-end validation
Reproduce and eliminate the VulkanPipelineState 0xC0000005 crash on a discrete-GPU Windows machine, enable Khronos validation layers to find root causes, and push the render loop from the first triangle to a full PBR scene.
Planned · Phase 2
Advanced render features into the main pipeline
Move ReSTIR, SVGF, path tracing and MicroCluster from algorithm prototypes into SceneRendererReal, validating performance and image quality on real GPUs.
Planned · Phase 3
Repo hygiene & CI loop
Clean up historical analysis documents and D3D12 leftovers in the repo root, add automated build coverage for the C++ bridge project, and establish a complete CI/CD pipeline.
