06 / FAQ

Some honest answers.

The ten most-asked questions about Yama. We don't dodge the sharp ones — including "does it actually run today" and "can I use it for a commercial project".

Is Yama a game engine or a modeling tool?

Both. Yama is positioned as an "integrated game & modeling engine" — it runs games like Unreal and edits assets like Blender. The WinUI 3 editor has five work modes: scene, terrain, modeling, code and test. Modeling mode edits mesh geometry directly, without jumping out to Blender.

That said, DCC bridges also exist — if you prefer the Blender / Maya modeling experience, LiveLink syncs assets in real time.

Why C# instead of C++?

Because C# lets us write faster, safer and more readable code. The .NET 10 JIT already produces machine code close to C++, especially with Span<T>, unsafe and SIMD intrinsics. The physics engine's GJK / EPA is entirely hand-written C#, and performance is within acceptable range.

More importantly: C# iterates 3-5× faster than C++. For a project maintained by one person, speed is everything.

What is Vulkan 1.4? Why only one backend?

Vulkan 1.4 is the Khronos Group's latest graphics API standard (released 2024), with modern features like dynamic rendering, mesh shaders and ray tracing. We maintain only one backend because the D3D12 backend was deprecated and removed from the project — maintaining two backends would slow everything down.

Linux / macOS support via a Vulkan translation layer (like MoltenVK) is theoretically possible, but Yama currently runs on Windows only, because the WinUI 3 editor depends on Windows.

Does it run today?

Depends on what "run" means. The engine compiles, the editor starts, assets load, and you can see a Vulkan-rendered triangle in the viewport — all of that works.

But the full end-to-end flow of PBR scene rendering + physics simulation + animation + audio still has Vulkan runtime crashes to solve on some discrete-GPU machines (see "Honest Status"). We're attacking this in Phase 1.

Can I use it for a commercial project?

Yama uses the MIT license, so there's no legal barrier to commercial use. But frankly, the current maturity isn't fit for production — the render pipeline's advanced features aren't yet stable on real GPUs, and the editor hasn't been through long-duration stability testing.

If you want to prototype, learn engine architecture, or contribute code — now is a great time. If you want to ship a game — wait a bit longer.

How do I contribute?

Clone the repository, open YamaEngine.sln in Visual Studio 2026 or JetBrains Rider, and hit F5 to build. Start reading from the YamaVulkanSandbox project — it has the most minimal engine usage examples.

Where help is needed most right now: GPU end-to-end debugging, Vulkan validation layer triage, CI/CD setup, and documentation.

Is the physics a PhysX wrapper?

No. Yama's physics engine has zero third-party dependencies — GJK / EPA / SAT collision detection, 9 joint constraint types, and the custom vector & quaternion libraries are all hand-written from the math up. This is the most direct expression of the "code is the documentation" principle — every line you read is our own.

How far along is the render pipeline?

PBR materials, cascaded shadows, skeletal skinning and temporal anti-aliasing (TSR) are wired into the SceneRendererReal main pipeline. ReSTIR global illumination, SVGF, path tracing and MicroCluster have complete algorithm code written, but aren't integrated into the main pipeline or validated on real GPUs yet — that's Phase 2.

How is it different from Godot?

Godot is a mature, large-community, cross-platform open-source engine. Yama doesn't aim to replace it — the positioning is different: a single Vulkan backend + hand-written core systems + a WinUI 3 integrated editor, closer to "a readable UE5-class desktop engine".

If you want to make a 2D game right now, use Godot. If you want to study how a modern render pipeline gets built from zero, come read Yama.

Why is there a Tang poem on the homepage?

Because "the storm is coming, the wind fills the tower" is a poetic description of the engine's current state — compilation is at zero (the mountain rain approaches), but the real GPU end-to-end validation hasn't run yet (the wind hasn't filled the tower).

All eight lines of 《咸阳城东楼》 ("East Tower of Xianyang City" by Xu Hun) are typeset as art in a standalone poem page — vertical layout, large type, six sunset color bands. Take your time.
