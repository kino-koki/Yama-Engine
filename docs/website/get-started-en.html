Quick Start

Get the engine
running in ten minutes.

No 100GB download like Unreal, no activation flow like Unity. Clone the repo, install one .NET SDK — from build to opening the editor, every step is real and verifiable.

Clone the repository
Q-1 Prerequisites

Before starting, you need
three things.

Windows 10/11 x64 · .NET SDK 10 (the repo's global.json pins 10.0.203) · a Vulkan 1.3+ capable GPU and driver. The C++ bridge and editor window need Visual Studio 2022 (with the desktop workload), but building the engine library and running tests do not.

01

Get the code

~1 min · Git

Clone the repository and enter it. The repo is small; cloning is quick.

git clone https://github.com/kino-koki/Yama-Engine.git cd Yama-Engine
02

Restore dependencies

~2 min · dotnet restore

Restore NuGet packages. Silk.NET (Vulkan bindings), xUnit and other dependencies download automatically.

dotnet restore YamaEditor.sln
NoteThe repo ships a NuGet.config; on constrained networks, first confirm api.nuget.org is reachable.
03

Build the engine core library

~1 min · 0 errors 0 warnings

YamaEngine is the engine core library (~320K lines of C#). All managed projects currently build with 0 errors and 0 warnings; any new warning fails the build via -warnaserror.

dotnet build YamaEngine\YamaEngine.csproj -c Debug // expected output (tail) // Build succeeded. 0 Warning(s) 0 Error(s)
04

Run the test suite

~3 min · 1559 cases

Tests cover physics analytic solutions, ECS, animation state machines, render post-processing and more. A full green run means your environment is set up correctly.

dotnet run --project YamaEngine.Tests\YamaEngine.Tests.csproj // expected output (tail) // All YamaEngine tests passed.
05

Open the editor

~2 min · WinUI 3 + Vulkan

The editor is a WinUI 3 shell hosting a Vulkan viewport. Shaders compile on first launch — give it a moment.

dotnet build YamaEditor\YamaEditor.csproj -c Debug dotnet run --project YamaEditor\YamaEditor.csproj
Honest noteThe Vulkan runtime still has stability issues on some drivers (a historical 0xC0000005) — this is the top-priority fix. If you hit a crash, please file an Issue with the log.
06

Change a line, watch hot-reload

Optional · Roslyn scripting

Change a log line in the YamaCLI sandbox and experience runtime script hot-reload — no process restart needed.

dotnet run --project YamaCLI\YamaCLI.csproj
