06 / FAQ

一些诚实的回答。

关于 Yama 最常被问到的十个问题。我们不回避尖锐的问题 — 包括"现在到底能不能跑"和"能不能用于商业项目"这两个最直接的问题。

Yama 是游戏引擎还是建模工具？

两者都是。Yama 的定位是"游戏与建模一体化引擎" — 像 Unreal 一样运行游戏，也像 Blender 一样做资产编辑。WinUI 3 编辑器里有五种工作模式：场景、地形、建模、代码、测试。建模模式直接编辑网格几何体，不需要跳出去用 Blender。

当然，DCC 桥接也存在 — 如果你更喜欢 Blender / Maya 的建模体验，LiveLink 能把资产实时同步进来。

为什么选 C# 而不是 C++？

因为 C# 让我们写得更快、更安全、更容易读。.NET 10 的 JIT 已经能生成接近 C++ 的机器码，特别是配合 Span<T>、unsafe 和 SIMD intrinsics。物理引擎的 GJK / EPA 全部手写 C#，性能在可接受范围内。

更重要的是：C# 的开发迭代速度是 C++ 的 3-5 倍。一个人维护的项目，速度就是一切。

Vulkan 1.4 是什么？为什么只有一个后端？

Vulkan 1.4 是 Khronos 最新的图形 API 标准（2024 发布），包含动态渲染、Mesh Shader、Ray Tracing 等现代特性。我们只维护一个后端是因为 D3D12 后端已经被废弃并从工程中移除 — 维护两个后端会拖慢整体进度。

Linux / macOS 支持通过 Vulkan 移植层（如 MoltenVK）理论上可行，但目前 Yama 只在 Windows 上运行，因为 WinUI 3 编辑器依赖 Windows。

现在能跑起来吗？

取决于"跑起来"的定义。引擎能编译、能启动编辑器、能加载资产、能在视口里看到 Vulkan 渲染的三角形 — 这些都工作了。

但完整的 PBR 场景渲染 + 物理模拟 + 动画 + 音频的端到端流程，目前在部分独显机器上还有 Vulkan 运行时崩溃需要解决（详见"真实状态"）。我们正在 Phase 1 集中攻克这个问题。

能用于商业项目吗？

Yama 使用 MIT 许可，商业使用没有法律障碍。但坦率地说，当前成熟度不适合生产环境 — 渲染管线的高级特性尚未在真实 GPU 上稳定，编辑器也未经过长时间使用的稳定性测试。

如果你想做原型实验、学习引擎架构、或者贡献代码 — 现在就是好时机。如果你想做一个要发布的游戏 — 再等等。

怎么参与贡献？

Clone 仓库，用 Visual Studio 2026 或 JetBrains Rider 打开 YamaEngine.sln，F5 编译。从 YamaVulkanSandbox 项目开始读，那里有最精简的引擎使用示例。

当前最需要帮助的方向：GPU 端到端调试、Vulkan 验证层问题定位、CI/CD 搭建、文档撰写。

物理引擎是封装的 PhysX 吗？

不是。Yama 的物理引擎零第三方依赖，GJK / EPA / SAT 碰撞检测、9 种关节约束、自定义向量与四元数库全部从数学公式开始手写。这是"代码即文档"原则最直接的体现 — 你读到的每一行都是自己的。

渲染管线到哪一步了？

PBR 材质、级联阴影、骨骼蒙皮、时间抗锯齿（TSR）已接入 SceneRendererReal 主管线。ReSTIR 全局光照、SVGF、路径追踪、MicroCluster 已写出完整算法代码，但尚未接入主管线并在真实 GPU 上跑通 — 这是 Phase 2 的内容。

和 Godot 有什么区别？

Godot 是一个成熟、社区庞大、跨平台的开源引擎。Yama 不打算替代它 — Yama 的定位不同：单一 Vulkan 后端 + 手写核心系统 + WinUI 3 一体化编辑器，更像一个"可读性的 UE5 级桌面引擎"。

如果你想马上做一个 2D 游戏，用 Godot。如果你想研究一个现代渲染管线怎么从零搭起来，来读 Yama。

为什么首页放一首唐诗？

因为"山雨欲来风满楼"正好是引擎当前状态的诗意写照 — 编译已经清零（山雨将至），但真正的 GPU 端到端验证还没跑通（风还没满楼）。

《咸阳城东楼》八句被完整艺术字化排进 独立诗页，竖排、大字、六段日落色阶，可以慢慢读。

山雨欲来风满楼。
唐 · 许浑《咸阳城东楼》

编译错误已经清零，好比山雨将至；而真正的 GPU 端到端验证还没有跑通 —— 风尚未满楼。这是引擎此刻的真实状态，也是下一阶段要集中攻克的事。
